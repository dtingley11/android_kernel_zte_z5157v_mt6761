# Z5157V MT6761 kernel port

Work in progress for the ZTE Blade A3 Prime (Z5157V). Linux 4.9.190,
32-bit ARM. No device boot or peripheral testing has been performed.

## Source and configuration

- Vendor tree: [Smu1zel/android_kernel_zte_Z3153](https://github.com/Smu1zel/android_kernel_zte_Z3153),
  revision `271f50e97d5ab64a7c7caa86e53e7bb720047ef3`.
  Despite its repository name, this tree contains the Z5157V `mango` board,
  camera, display and touchscreen sources. It is a vendor-source port,
  not a verified complete Z5157V release.
- KernelSU Next: [v1.0.8](https://github.com/KernelSU-Next/KernelSU-Next/tree/9d9f9ed5d5f3a66a2f44e24c926075554f9275ce),
  revision `9d9f9ed5d5f3a66a2f44e24c926075554f9275ce`, vendored in
  `KernelSU-Next/kernel`. Build version is fixed at `12701`.
- `arch/arm/configs/z5157v_defconfig` starts from the configuration extracted
  from the supplied stock-kernel TWRP image. Original config SHA-256:
  `0d8760e0ff79a53efba5b51d500f6f5bbd78d1ba6d2ef59da7dc8b2ce991fb1e`.
  Board is `mango/mt6761`, overlay `mango/k61v1_32_bsp_hdp`.

The earlier Linux 4.4 repository remains separate. Its MT6739 build is not
an image for this phone.

## Build

Use an ARM Android GCC 4.9 toolchain and a GNU/Linux host with the kernel
build dependencies installed:

```sh
CROSS_COMPILE=/path/to/arm-linux-androideabi- JOBS=12 \
  ./build-ksu.sh z5157v_defconfig ../out/z5157v objects
# Full kernel and device trees, after resolving the missing panel source:
CROSS_COMPILE=/path/to/arm-linux-androideabi- JOBS=12 \
  ./build-ksu.sh z5157v_defconfig ../out/z5157v image
```

Builds are offline. Host tools use `-fcommon` for the older device-tree
compiler. SELinux generated headers are prepared before compiling KSU.

## KernelSU integration

Source hooks cover exec, read, faccessat, stat and input events. Native LSM
callbacks cover prctl, setuid, inode rename, devpts and keyring handling.
Each interface has one hook path; kprobes are disabled. Required credential
and path-unmount helpers are included in source, retaining capability,
namespace, locked-mount and LSM checks.

ARM32, legacy read/write APIs, certificate parsing and smaller kernel
stacks are handled by the vendored compatibility changes. Package/signature
verification remains that of KernelSU Next. SELinux enforcing settings and
module signature enforcement from the stock configuration are retained.

Validation: KernelSU and all source-hook objects compiled with GCC 4.9 and
linked together without unresolved KernelSU hooks or kprobe dependencies.
This verifies compilation and hook linkage only.

## Device build blocker

The stock config names six display drivers. Five are included, but
`zte_mango_zhongguangdian_er68577_720p_5p45_boe` is missing. The unmodified
vendor tree fails its full build for that reason. The official
`Z5156CC_Android10(10.0)_Kernel(4.9.190)` archive also lacks this driver
(archive SHA-256 `78e3872577ae119fd9485665ead17a2ec9db2e71c9c04360b6e5132bf740285b`).
The missing driver has not been removed from the defconfig or replaced
with another panel's initialization sequence. Confirm the phone's actual
panel and obtain matching source before producing a device image.

Runtime checks still required: boot, display and touch, cameras, modem,
storage, Wi-Fi, audio, suspend, SELinux denials, signed module loading,
KernelSU manager authorization, root grants and module mount cleanup.
