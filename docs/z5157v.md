# Z5157V MT6761 kernel port

Work in progress for the ZTE Blade A3 Prime (Z5157V). Linux 4.9.190,
32-bit ARM. No device boot or peripheral testing has been performed.

## Source and configuration

- Vendor tree: [Smu1zel/android_kernel_zte_Z3153](https://github.com/Smu1zel/android_kernel_zte_Z3153),
  revision `271f50e97d5ab64a7c7caa86e53e7bb720047ef3`.
  Despite its repository name, this tree contains the Z5157V `mango` board,
  camera, display and touchscreen sources. It is a vendor-source port,
  not a verified complete Z5157V release.
- KernelSU Next: [v1.0.8](https://github.com/KernelSU-Next/KernelSU-Next/tree/9d9f9ed5d5f3a66a2f44e24c926075554f9275ce),
  revision `9d9f9ed5d5f3a66a2f44e24c926075554f9275ce`, vendored in
  `KernelSU-Next/kernel`. Build version is fixed at `12701`.
- `arch/arm/configs/z5157v_defconfig` starts from the configuration extracted
  from the supplied stock-kernel TWRP image. Original config SHA-256:
  `0d8760e0ff79a53efba5b51d500f6f5bbd78d1ba6d2ef59da7dc8b2ce991fb1e`.
  Board is `mango/mt6761`, overlay `mango/k61v1_32_bsp_hdp`.

The earlier Linux 4.4 repository remains separate. Its MT6739 build is not
an image for this phone.

## Build

Use an ARM Android GCC 4.9 toolchain and a GNU/Linux host with the kernel
build dependencies installed:

```sh
CROSS_COMPILE=/path/to/arm-linux-androideabi- JOBS=12 \
  ./build-ksu.sh z5157v_defconfig ../out/z5157v objects
# Full kernel and device trees, after resolving the missing panel source:
CROSS_COMPILE=/path/to/arm-linux-androideabi- JOBS=12 \
  ./build-ksu.sh z5157v_defconfig ../out/z5157v image
```

Builds are offline. Host tools use `-fcommon` for the older device-tree
compiler. SELinux generated headers are prepared before compiling KSU.

## KernelSU integration

Source hooks cover exec, read, faccessat, stat and input events. Native LSM
callbacks cover prctl, setuid, inode rename, devpts and keyring handling.
Each interface has one hook path; kprobes are disabled. Required credential
and path-unmount helpers are included in source, retaining capability,
namespace, locked-mount and LSM checks.

ARM32, legacy read/write APIs, certificate parsing and smaller kernel
stacks are handled by the vendored compatibility changes. Package/signature
verification remains that of KernelSU Next. SELinux enforcing settings and
module signature enforcement from the stock configuration are retained.

Validation: KernelSU and all source-hook objects compiled with GCC 4.9 and
linked together without unresolved KernelSU hooks or kprobe dependencies.
This verifies compilation and hook linkage only.

## Device build blocker

The stock config names six display drivers. Five are included, but
`zte_mango_zhongguangdian_er68577_720p_5p45_boe` is missing. The unmodified
vendor tree fails its full build for that reason. The official
`Z5156CC_Android10(10.0)_Kernel(4.9.190)` archive also lacks this driver
(archive SHA-256 `78e3872577ae119fd9485665ead17a2ec9db2e71c9c04360b6e5132bf740285b`).
The missing driver has not been removed from the defconfig or replaced
with another panel's initialization sequence. Confirm the phone's actual
panel and obtain matching source before producing a device image.

Runtime checks still required: boot, display and touch, cameras, modem,
storage, Wi-Fi, audio, suspend, SELinux denials, signed module loading,
KernelSU manager authorization, root grants and module mount cleanup.

## SUSFS integration

SUSFS [Linux 4.9 v1.5.5 source](https://github.com/wxx9248/susfs4ksu/tree/41ba0b533b8524a0ba95a5952506a75f17355450),
revision `41ba0b533b8524a0ba95a5952506a75f17355450`, supplies
`50_add_susfs_in_kernel-4.9.patch`, the KernelSU interface patch,
`fs/susfs.c` and the two `include/linux/susfs*.h` headers. All required
kernel source is committed directly; no submodule or setup download is
needed. Its matching userspace control tool and license are under
`tools/susfs`.

The Linux 4.9 patch was adapted to this 4.9.190 vendor tree. The two
getdents hooks retain this tree's existing buffer checks. KernelSU-side
prctl commands, initialization, SELinux SID helpers, post-fs-data flags
and mount cleanup are adapted to Next v1.0.8. Next's manager signature
checks, existing function names and additional cleanup paths are retained.
The upstream patch's build-time source edits and warning suppression were
not imported.

Compatibility corrections include conditional fdinfo declarations,
`d_path()` error-pointer checks, reference cleanup, bounded userspace
strings, 64-bit stat logging and terminating mount-parent walks at the
namespace root. Ordinary statfs lookups retain their original dentry.
Command-line replacement uses a mutex and a complete copied string, avoiding
user-memory access under a spinlock. Mount-inode lookup runs outside its
update spinlock.

### Revision selection and hooks

The inspected KernelSU Next revisions were:

| Revision | Result |
| --- | --- |
| `legacy` — `b933b1f728116a456fbebf27b6a8772a640cdf23` | No SUSFS integration; newer hook interfaces require additional old-kernel/ARM32 work. |
| `dev` — `a6c81fa4a8b7341d0bc5c3e4507531459df871ae` | Contains SUSFS interfaces associated with its newer module/hook implementation. Not used here. |
| `susfs-x64-test` — `212631f1b47829cfecfd4857b8526533034bf0b4` | Architecture-specific alternative, not selected for ARM32. |
| `v3.1.0-legacy-susfs` — `ba4422f0556e10f40dda1887631d87a18ede4ec5` | Already contains SUSFS v2 interfaces and requires `THREAD_INFO_IN_TASK`; not selected. |
| `v1.0.8` — `9d9f9ed5d5f3a66a2f44e24c926075554f9275ce` | No existing SUSFS implementation; selected for its legacy source/LSM hook interfaces. |

The SUSFS v2.3 Linux 4.9 branch at
`71345ded5af28f55d76ebcdc7a9df9cea56111e1` targets a different KernelSU
interface. This port uses the earlier v1.5.5 interface instead. The supplied
sidex15 GitHub URL was unavailable when inspected.

SUSFS v1.5.5's non-GKI implementation explicitly drops `SUS_SU` because
of conflicts with manual hooks. No `SUS_SU` driver or probe-switching
mechanism is enabled here. `CONFIG_KSU_MANUAL_HOOK=y` supplies KSU's exec,
read, access, stat and input entry points; native LSM callbacks supply the
remaining KSU entry points. SUSFS uses those existing KSU callbacks for
its control and process classification, plus its own filesystem hooks.
There is no second KSU manual-hook implementation.

### Features and validation

`CONFIG_KSU_SUSFS=y` is set in `z5157v_defconfig`.

| Feature | Defconfig | Verification |
| --- | --- | --- |
| Mount hiding and mount ID handling | Enabled | Compiled and linked; runtime pending |
| Automatic marking of default KSU mounts | Enabled | Compiled and linked; runtime pending |
| File stat and map inode/device spoofing | Enabled | Compiled and linked; runtime pending |
| Explicit unmount paths and KSU cleanup integration | Enabled | Compiled and linked; runtime pending |
| Uname spoofing | Enabled | Compiled and linked; runtime pending |
| Kernel logging control | Enabled | Compiled and linked; runtime pending |
| `/proc/cmdline` spoofing | Enabled | Compiled and linked; runtime pending |
| Path hiding, automatic bind-mount rules, open redirection | Disabled | Source included; not verified |
| Overlayfs-wide stat spoofing and kallsyms filtering | Disabled | Source included; not verified |
| Magic-mount handling, `SUS_SU` | Disabled/unavailable | Not part of the selected runtime configuration |

Use matching Next v1.0.8 manager/userspace with its overlayfs backend.
The upstream `embed_ksud.c` is a stub; matching userspace must be installed
by the manager. A current manager or SUSFS v2 userspace is not a verified
substitute. KSU's matching overlayfs userspace uses the `KSU` mount-source
name expected by this SUSFS cleanup interface.

The included SUSFS control tool must be built for **32-bit ARM**, matching
this kernel's native structure layout. Upstream's packaged ARM64 executable
is unsuitable. Build the included source with Android NDK:

```sh
/path/to/android-ndk/ndk-build NDK_PROJECT_PATH="$PWD/tools/susfs" \
  NDK_OUT="$PWD/../out/susfs-tool" NDK_LIBS_OUT="$PWD/../out/susfs-tool-libs"
```

NDK r27d compiled the included tool as an ARM EABI5 static executable for
Android API 21. The binary has not been run on the device.

Combined validation used ARM Android GCC 4.9.x 20150123 and `HOSTCFLAGS=-O2
-fcommon`:

- Stock-based Z5157V configuration: KSU, SUSFS and all modified source-hook
  objects compile and link together without unresolved KSU/SUSFS references.
- Full stock-based `vmlinux dtbs` build: blocked by the missing ER68577 BOE
  driver, as with the unmodified base source.
- Separate five-panel compile check: `vmlinux` links and mango DTB/overlay
  compile. No strong undefined symbols remain. Three weak optional platform
  symbols remain: `__ddp_mem_test`, `mlog_get_buffer`, `report_hub_dmd`.
  The GPU driver compiles and links without the changes used in the earlier
  Linux 4.4 BSP experiment.
- Kprobes remain disabled. SELinux settings and module-signing enforcement
  match the extracted stock configuration. No enabled stock configuration
  setting is dropped. The already-disabled `SCREEN_ON_TEMP_SUPPORT` symbol
  disappears during Kconfig normalization because its dependency is absent.

To reproduce the five-panel compile/link check without changing the device
configuration:

```sh
CROSS_COMPILE=/path/to/arm-linux-androideabi- JOBS=12 \
  KERNEL_EXTRA_CONFIG=kernel/configs/z5157v-compile-check.config \
  ./build-ksu.sh z5157v_defconfig ../out/z5157v-check objects
make O=../out/z5157v-check ARCH=arm CROSS_COMPILE=/path/to/arm-linux-androideabi- \
  HOSTCFLAGS='-O2 -fcommon' -j12 vmlinux dtbs
```

That fragment omits one panel solely for build verification. It does not
establish which panel the phone contains or produce a verified device image.

Device validation must check all enabled SUSFS controls, non-root app versus
root/manager behavior, ordinary mount/stat/proc behavior, namespace creation,
module cleanup, SELinux enforcement and denials, and reboot/suspend stability.
Passing compilation does not establish that hiding or spoofing works.
